

## November 7 — restrict configured text-generation workers

Before launching the planned fresh AES exploration, source review and installed
CLI configuration listings showed that a read-only temporary cwd plus a
no-tools instruction still exposes inherited MCP tools. Empty MCP tables did
not remove node_repl. This is a real capability/configuration gap, not a new
FPGA design failure. No model turn, server connection or board action was used
to diagnose it. Recorded taxonomy precedes implementation.

Smallest correction: preserve the existing login, managed/security environment
and read-only sandbox; ignore user configuration for worker execution; disable
supported execution/app/plugin/hook/browser/computer/image/delegation features
and web search. Discover configured server names without connecting them,
construct complete inert disabled entries, then require no enabled MCP server
in the effective inventory. Unknown/malformed inventory, unsupported settings
or unresolved capabilities block before generation. No weaker fallback.
Post-execution text-event validation is additional acceptance checking; it
cannot prevent or undo earlier side effects and is not an isolation proof.

Acceptance: before/after backend tests, synthetic parser fixture, precise
timeout/cancellation/quota/auth/redaction regressions; model-free actual CLI
profile validation; one harmless bounded model control with no hardware
operations; complete harness and tooling regression on unchanged inputs.
Configuration checks share the original worker timeout rather than extending
it. Preserve every failed probe; do not strip authentication or sandbox/network
environment. Document default-model/provider semantics when ignoring user config.
The public benchmark still needs an independently qualified grading boundary.
Only after this passes: commit/freeze and run one current-tier AES exploration
with its original metadata limits. No lower-tier re-holds or board operations.
