# Basys 3 UART echo bring-up

Hand-written first hardware step: proves the path from Verilog to running
hardware on the Digilent Basys 3 (`xc7a35tcpg236-1`). The board echoes every
byte sent over its USB-UART and shows the last byte on LD0–LD7. LD15 latches
if a byte was ever dropped, and LD14 if a frame arrived with a low stop bit.
`btnC` resets. It is not generated by the harness. Later board work builds on
these constraints, scripts and the PC-side checker.

| Path | Contents |
|---|---|
| `rtl/` | `uart_rx` (two-flop synchronizer, mid-bit sampling, glitch rejection, frame-error and break handling), `uart_tx` (stop bit 1/16 bit short), `sync_fifo`, `basys3_uart_echo` (top) |
| `constraints/` | Pins from Digilent's Basys-3-Master.xdc, 100 MHz clock |
| `sim/` | Self-checking testbench with three scenarios (see below) |
| `scripts/` | `build.tcl`, `program.tcl`, `run_sims.ps1`, `echo_test.py` |

Settings: 100 MHz clock, 115200 baud 8N1 (868 clocks per bit), 16-byte FIFO.

**Why the stop bit is short.** An echo must send bytes at least as fast as
they arrive, or its FIFO eventually overflows. The PC's UART sends about 0.15%
faster than an exact 115,200 baud. With a full stop bit, the first version
lost its first byte after 9,696 bytes of continuous traffic. Shortening only
the transmitted stop bit makes the echo 0.6% faster than the nominal rate.
Receivers sample the middle of the stop bit, so they still accept it.

## Verified results (October 28, 2026)

Vivado 2025.2 and a physical Basys 3 on USB. The full record is in
[evidence 02](../../../evidence/2026-10-28/basys3-uart-echo-02/README.md); the
first, superseded version is in
[evidence 01](../../../evidence/2026-10-28/basys3-uart-echo-01/README.md).

| Check | Result |
|---|---|
| Simulation | Exact rate with glitch, bad-frame, break and reset checks; a sender 0.5% fast with no loss; a sender 3% fast latches the overflow flag |
| Fault checks | Reverting the stop-bit fix fails the 0.5%-fast scenario; reverting the break wait fails the break check |
| Implementation | 0 warnings; setup +4.529 ns, hold +0.106 ns; 77 LUTs, 94 FFs, 14 IOBs |
| Hardware, line-rate stream | 1,000,000 random bytes, 0 missing, 0 mismatches, 11,537 bytes/s |
| Negative control, PC at 57600 | Fails as required |

## Run it

From this folder, with the board plugged in and switched on:

```powershell
$vivado = "C:\AMDDesignTools\2025.2\Vivado\bin"
New-Item -ItemType Directory -Force build | Out-Null
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_sims.ps1
& "$vivado\vivado.bat" -mode batch -nojournal -log build/vivado_build.log -source scripts/build.tcl
& "$vivado\vivado.bat" -mode batch -nojournal -log build/program.log -source scripts/program.tcl
python scripts/echo_test.py --bytes 1000000
```

`echo_test.py` streams at line rate by default. Use `--mode chunked` to send a
chunk and wait for its echo, and `--port COMn` to pick the port. It finds the
Basys 3 UART on its own (FTDI interface B). Programming loads the FPGA's SRAM
only and is lost at power-off. Vivado use follows the single-queue rule in
`docs/AGENT_HANDOFF.md`.
